# Security Policy

## Scope

EdgeAfterCosts is paper-only research software. It holds no exchange
credentials, has no order-execution path, and reads public market data only.
That narrows the threat surface considerably, but the following are all in
scope:

- **Anything that could create an order-execution path**, or that weakens or
  bypasses the paper-only guard in `api/app/safety.py`. This is the highest
  severity class in this project.
- Authentication and session handling in the API and dashboard (session cookies,
  CSRF, the bootstrap admin flow).
- Credential or secret leakage — into logs, API responses, the JS bundle, the
  database, or the repository itself.
- Injection, deserialisation or path-traversal issues in the API, the worker, or
  the research CLIs.
- Dependency vulnerabilities with a demonstrated path to exploitation here.
- Container and deployment configuration that would expose the database, Redis,
  or the API beyond what the documentation states.

## Out of scope

- The profitability, correctness or wisdom of any trading strategy. That is a
  research question, not a security issue — open a normal issue.
- Findings that require an attacker to already have shell access to the host.
- Reports generated by an automated scanner with no analysis of whether the
  finding is reachable in this codebase.

## How to report

**Please do not open a public issue for a security vulnerability.**

Use **GitHub's private vulnerability reporting** on this repository:
open the **Security** tab, choose **Report a vulnerability**, and submit the
report there. It is visible only to the maintainers until a fix is published.

If private vulnerability reporting is not enabled on the repository you are
looking at, open a public issue that says only that you have a security report
and asks a maintainer to enable it — **without any details of the finding**.

## What to include

- The version or commit you tested.
- What the vulnerability allows an attacker to do.
- Steps to reproduce, ideally minimal.
- Any suggested remediation.

For a finding in the paper-only guard, please describe the *class* of bypass
rather than shipping a working exploit.

## What to expect

- Acknowledgement of the report.
- An assessment of severity and scope, and whether it is in scope as above.
- A fix or a documented decision, and credit in the release notes if you want it.

This is a volunteer-maintained research project. There is no bug bounty and no
contractual response time.

## Supported versions

Only the default branch is supported. There are no maintained release branches.
